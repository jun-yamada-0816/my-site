# 星と海

1995年頃の個人ホームページをイメージした、静的HTMLとSupabaseのサイトです。
トップページは `index.html`、共通のレトロな見た目は `retro.css`、海のドット絵は `assets/starlit-sea.svg` にあります。

## スマホを基準にした表示

CSSの基本指定は1列表示です。480px以上でボタンなどを横に並べ、640px以上で紹介文と画像を2列にし、1024px以上で左側の目次を表示します。
本文は16pxを基準とし、主要な操作は44px以上のタップ領域を確保しています。「表示設定」の文字サイズ変更にも対応します。
スマホの下部には「ページ上部へ」「つらいとき」を配置し、ノッチやホームバーの余白を確保しています。編集画面は画面の高さに合わせて内部をスクロールできます。

## プロフィールの編集

1. 画面上部の鍵アイコン、または最下部の「管理者メニュー」を開きます。
2. これまでと同じ管理者アカウントでログインします。
3. 「PROFILE / プロフィールを編集する」を選びます。
4. お名前、ひとこと、自己紹介、好きなもの、インターネットを始めた年を入力し、「保存して公開する」を押します。

自己紹介の改行はそのまま表示します。好きなものと開始年は空欄にすると非表示です。
保存に失敗した場合は入力を残し、エラーを表示します。

### 保存先

追加のSQL設定を必要としないよう、既存の `blog_posts` テーブルに、専用の固定ID `00000000-0000-4000-8000-000000000095` を持つプロフィール文書を保存します。
タイトルは `__site_profile_v1__`、本文は `version: 1` とプロフィール各項目を含むJSONです。
閲覧と編集には既存の公開読み取り・管理者認証のRLSを使用します。既存サイトと同じく、Supabaseの認証アカウントは管理者専用であることが前提です。

このIDは日記の取得時にサーバー側で除外し、更新履歴の日記一覧にも含めません。プロフィールを追加するまでは初期紹介文を表示します。
ほかのクライアントから `blog_posts` を一覧取得するときも、このIDを除外してください。プロフィール本文はHTMLとして実行せず、文字列として表示します。

カウンターは既存の `site_visits` と `increment_visit_count` を使用します。同じブラウザでは1日1回、管理者ログイン中は加算せず、取得に失敗した際に架空の数字は表示しません。

## 動作確認

PlaywrightとChromiumがある環境で次を実行します。

```sh
node tests/retro.cjs
```

必要に応じて `PLAYWRIGHT_PATH` でPlaywrightのモジュール位置、`CHROMIUM_PATH` でChromiumの実行ファイルを指定できます。
テストはローカルHTTPサーバーを起動します。最初の実行ではサイトが使うTailwindとSupabaseの公開CDNファイルを一時フォルダに取得します。
Supabaseへの通信はすべてテスト内で置き換えるため、本番の投稿・プロフィール・訪問者数は変更しません。

確認範囲は、ログイン、プロフィールの編集・保存・失敗・再表示・匿名閲覧、ログアウト、日記との分離、HTMLの文字列表示、カウンターの重複防止と通信失敗時の再試行、ナビゲーションと既存モーダルです。
レスポンシブ表示はタッチ端末のエミュレーションで320〜1440pxの9段階を通常文字・大きい文字の両方で確認し、横へのはみ出し、本文サイズ、主要なタップ領域を検査します。プロフィール編集では小型画面、横向き、高さ460pxの画面でも保存ボタンに到達できることを確認します。実機のソフトウェアキーボード操作は対象外です。
スクリーンショットはOSの一時フォルダ内の `my-site-check` に保存します（`TEST_OUTPUT` で変更可能）。実際の管理者アカウントでの本番保存は自動テストの対象外です。
